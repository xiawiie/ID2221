# ID2221 第 1 周设计报告

**项目：** 通用城市数据集成平台  
**小组成员：** 提交前补充姓名与 KTH ID  
**证据生成日期：** 2026 年 9 月 12 日

## 1. 目标与已验证结果

本项目实现了一个基于 Spark 与 Delta Lake 的可复用城市数据平台，用于整合异构数据。平台摄取 2024 年前三个月的纽约黄色出租车行程（Parquet）、逐小时天气（CSV）、逐小时 PM2.5（CSV）以及 TLC 出租车区域对照表（CSV）；对输入契约进行校验和标准化，记录数据血缘与运行元数据，隔离结构性无效记录，并写入 Bronze、Silver 和 Gold Delta 表。

已验证运行共接收 9,551,977 条出租车行程，隔离 2,801 条下车时间不晚于上车时间的行程。Silver 层包含 265 个出租车区域、8,784 个天气小时和 8,784 个聚合后的纽约市 PM2.5 小时。Gold 表 `integrated_taxi_trips` 恰有 9,551,977 行，即每条有效行程对应一行富化记录。上车和下车区域连接均为 100% 命中。19 条上车时间落在 2024 年范围外的行程未匹配天气和空气质量；它们被保留，环境字段为 NULL，并带有明确的匹配状态。

## 2. 数据目录

| 数据集 | 实体与记录键 | 连接与时间 | 类别值与增长方式 |
| --- | --- | --- | --- |
| 黄色出租车行程 | 一行是一趟行程。源数据没有已证实唯一的自然键；以 SHA-256 生成的 `trip_id` 仅用于审计，不是业务主键。 | `PULocationID`、`DOLocationID` 连接区域表。上车时间以本地小时连接天气，以转换后的 UTC 小时连接 PM2.5。上、下车时间用于计算时长。 | 供应商、费率、支付方式、缓存标志和区域 ID 为类别值。每月新增文件使事实表持续增长。 |
| 天气 | 一行是一条全市逐小时观测。`year + month + day + hour` 唯一，并组成 `observation_ts_local`。 | 派生小时与按小时截断的 `pickup_ts_local` 相连。 | 天气编码和 `*_source` 字段为类别值；每小时新增一行。 |
| 出租车区域 | 一行是一个 TLC 出租车区域。`LocationID` 唯一且非空。 | `LocationID` 分别与上下车区域 ID 连接；无时间字段。 | Borough、Zone、service zone 为类别值；仅在 TLC 调整区域定义时低频变化。 |
| 空气质量 | 一行是一个站点、仪器通道在某小时的 PM2.5 测量。候选复合键为州、县、站点、参数、POC、本地日期和本地时间。 | GMT 日期和时间组成 `observation_ts_utc`。筛选纽约市后按站点聚合，再以 UTC 小时连接出租车。 | 站点、县、参数、方法、单位和质量标记为类别值；每站点每小时持续新增观测。 |

出租车数据中存在可选的 NULL 字段和可能代表冲正的负金额。负车费、负总额、与文件月份不符的上车时间和极端距离会被标记但保留。缺少核心时间、下车时间不晚于上车时间、重复天气小时、无效区域键或无效 PM2.5 值会被隔离。该策略将可疑业务事件与结构上不可用的记录区分开。

## 3. 存储架构与公共数据模型

原始文件在 `datasets/` 下保持不可变。`config/datasets.yml` 保存数据集契约、路径、预期 schema、schema 版本和源文件月份。生成的表采用以下结构：

```text
lakehouse/
  bronze/       原始值和血缘字段
  silver/       标准化且完成质量检查的数据集
  gold/         integrated_taxi_trips
  quarantine/   被拒绝记录及原因
  metadata/     ingestion_runs 运行记录
  benchmark/    Taxi Trips 的替代存储布局
```

Bronze 层统一加入 `_source_file`、`_source_sha256`、`_ingested_at`、`_run_id` 和 `_schema_version`。Silver 和 Gold 使用小写 `snake_case`；ID 使用整数，金额、距离和环境测量值使用 double，标志使用字符串，事件字段使用 timestamp。可选值和未匹配的上下文保持 NULL，而不被替换为零。

出租车时间保存为纽约本地墙上时钟字段 `pickup_ts_local` 与 `dropoff_ts_local`。天气时间由四个日期字段合成，并标记为时区未被源数据确认的本地墙上时钟。空气质量时间由 GMT 字段解析后以 UTC 保存。因此时间语义是明确的：天气采用本地小时连接，PM2.5 采用出租车上车时间转换后的 UTC 小时连接。

`taxi_zones`、`weather_hourly` 和聚合后的 `air_quality_hourly_nyc` 都很小，不分区，并在连接时广播。生产用出租车表按 `source_file_month` 分区，这是稳定的覆盖键。`pickup_month` 保留为数据列，因为少量行程实际不在其文件名表示的月份内。高基数字段、严重倾斜字段，或查询不筛选的字段若用于分区，会产生小文件和元数据开销而没有裁剪收益。数据量扩大 20 倍时，应保留按源哈希的增量摄取，先测量真实过滤模式再调整分区，定期合并小文件，并仅在有证据时按高频过滤列聚簇。

配套架构图为 `docs/architecture_diagram.png`：CSV/Parquet 源文件经过显式 schema 摄取，流向 Bronze、Silver、Gold Delta 层，并分出元数据、隔离和基准测试输出。

## 4. 通用摄取框架

统一编排流程分发 CSV 和 Parquet 读取器，应用显式 schema，注入 Bronze 血缘字段，执行校验，写入 Delta 表，追加隔离记录，并记录成功运行的统计信息。运行元数据表保存数据集键、源文件和哈希、schema 版本、运行 ID、读取/接收/隔离行数、时间戳和状态。源文件哈希与 schema 版本均未变化时跳过运行，使重复运行具备幂等性。

数据集专属逻辑被有意隔离：PySpark schema、字段重命名、时间生成、出租车质量规则、纽约 PM2.5 筛选和按小时聚合，反映了不同部门数据的粒度与业务语义。配置承担路径等运行差异，转换函数按数据集类型选择。这避免为每个月的出租车文件重复编写摄取脚本。未来增加 20 个数据集时，主要增加 YAML 条目；只有真正新增的物理 schema 或转换类型才需要新增代码和测试。

## 5. 集成策略

`integrated_taxi_trips` 通过顺序 left join 构建，并在每次连接后断言行数不变，以防止意外的行数膨胀。

| 上下文 | 关联规则 | 缺失数据策略 |
| --- | --- | --- |
| 上车/下车区域和 borough | `pu_location_id`、`do_location_id` 等值连接 `location_id`。 | 保留匹配状态列；当前所有行程均命中。 |
| 天气 | 将 `pickup_ts_local` 截断到小时，连接 `observation_ts_local`。 | 天气字段为 NULL，状态标记为 `missing`。 |
| 空气质量 | 将上车时间转换为 UTC 并截断到小时，连接纽约市逐小时 PM2.5 聚合。 | PM2.5 字段为 NULL，状态标记为 `missing`。 |

空气质量源在每小时有多个站点测量值，直接连接会复制出租车行程。因此平台先筛选纽约市 PM2.5 数据，再计算每小时一条全市估计值，包括中位数、均值、最小值、最大值和站点数，以保持出租车行程粒度。其局限性是：没有小时内插值，没有最近站点选择，也不能代表区域级暴露；筛选后的数据中 Manhattan 和 Staten Island 没有观测站。天气源没有站点 ID 或声明的时区，因此本地小时连接被明确记录为假设，而不是已证明的空间匹配。

## 6. 基准、工程决策与权衡

对相同的 9,551,977 条有效出租车行程物化了两种 Delta 布局：不分区和按 `pickup_month` 分区。每种布局先预热一次，再测量三次并报告中位数。

| 指标 | 不分区 | 按 `pickup_month` 分区 |
| --- | ---: | ---: |
| 源数据到 Delta 写入时间 | 18.453 s | 17.344 s |
| 数据大小 / 文件数 | 815.0 MiB / 10 | 820.0 MiB / 23 |
| 每 borough 行程数 | 527.601 ms | 558.957 ms |
| 每日平均行程时长 | 491.303 ms | 505.720 ms |
| 每 borough 平均车费 | 539.199 ms | 509.505 ms |

两种布局返回相同的结果签名。三项指定查询都扫描全时间范围且未按月份过滤，因此无法触发分区裁剪。写入和查询时间实际接近，而分区表产生了两倍以上的文件数。故当前工作负载建议使用不分区的基准存储；只有出现真实的按月查询或保留策略需求时才重新评估按月分区。完整方法和数据见独立文件 `docs/benchmark_report.md`。

## 7. 局限性与复现

源数据没有已证明的全局唯一出租车行程 ID，因此 `trip_id` 仅用于审计。天气时区和地理位置没有在源中声明。负金额可能是合法冲正，因此保留并标记。PM2.5 是全市估计，而非上车区域暴露。项目通过保留 NULL 和质量状态公开这些局限，而不是用插补或删除掩盖它们。

复现步骤和环境配置见 `README.md` 与 `docs/local_environment.md`。机器可读证据保存在 `artifacts/data_profile.json`、`artifacts/ingestion_verification.json`、`artifacts/integration_verification.json` 和 `artifacts/benchmark_report.json`。
